# Project 2 设计方案 v1

状态：设计提案，未开始开发、未完成试玩，不能据此宣称已达到满分或实测时长。日期：2026-10-14。

## 1. 设计定位

暂定名：Midnight Shift: The Last Lantern / 午夜班次：最后一盏南瓜灯。
Unity 3D、单人、第一人称环境解谜、轻度潜行、温暖的 Halloween 工厂。目标玩家喜欢探索、角色和轻量解谜，能使用键盘鼠标，不需要恐怖游戏经验。主线首次正常游玩目标 7–9 分钟，实际以试玩调整，评分要求为 5–10 分钟且无明显填充。

体验目标：从陌生访客变成被同事接纳的人，运用对机器与巡检规律的理解完成旧订单，再亲手把礼物送给一直照顾工厂的人。
借鉴用户提到的星露谷式地方归属感、日常人物和音乐氛围，不增加种田、日历、好感度刷取或经营系统。

## 2. 课程证据与修正

1. Theory of Fun，第 10、19 页：课程把游戏视为教会玩家某种东西的模拟；学习不应止于按键。第 36–40 页也区分了故事、审美享受和通过行动掌握问题。故事可以增强动机，但不能代替机制教学。
2. Rules of Play，第 45 页及后续：课件包括 Emergent Systems、Systems of Uncertainty、Systems of Information、Cybernetic Systems 等。注意 Systems of Information（86–95 页）和被略过的 Information Theory Systems（85 页）不是同一个标题。
3. Fundamentals of Game Design，第 21–23 页：gameplay mode 是某一时刻可用的玩法及相应界面，不能仅写 single-player；标题与暂停等应另列 shell screens。第 47 页说明 High Concept 在本课常可为一页。第 55 页说明 Game Script 主要是规则与核心机制，应足以支持不依赖电脑的玩法推演。第 54 页指出详细文字剧情需要附文字／对白稿。
4. The Art of Game Design，第 45–47 页要求明确实际技能，而非只写 problem solving；第 69–76 页强调挑战与成功、不同水平玩家试玩；第 115–120 页说明简单规则之间的互动可以产生复杂玩法。
5. 旧 Ballast 报告第 5–6 页已经写了有限空气下的路线规划及预警反应。因此不能把老师的批评归因为旧报告只写了空泛能力，也不能仅凭报告判断实际游戏是否兑现。需要对照实际游玩。旧报告记载的试玩时间和自动通关时间也不能否定老师四分钟完成的反馈。

## 3. 故事修订

工厂关闭后，姨妈一直负责保管建筑，今年准备把里面的物品交还原主。她请玩家回来取一张小时候留下的图纸。姨妈仍在小镇生活，不使用亲人去世作为默认煽情来源。

万圣节夜，留在工厂里的小幽灵会回来检查老机器。它们不是亡故工人的设定，而是多年制作玩具时留下的魔法小帮手。领班“小灯”一直保存着一张未完成订单。它不认识长大的玩家，把玩家当作姨妈请来的帮手。

订单正面的名字已模糊，纸张背面贴在装配图框里，起初只能看到南瓜灯图案。小灯以为是送给某个孩子的礼物，想在工厂清空前完成它。它的情绪障碍是担心自己做得不够好，不是故意隐瞒真相。

人物只承担必要功能：
- 小灯：领班和主要对话对象。认真、怕给别人添麻烦。开场说“这次一定能交货”。
- 纽扣：仓库管理员。保管物品、教玩家搬运，不擅自移动解谜货箱，避免剧情性格破坏玩家计划。
- 呼噜：巡检幽灵。对活跃机器与车间内的搬运行为进行检查。是善意但程序化的障碍，不表现为杀人怪物。

剧情节点：
1. 门厅：看到三只旧饭盒和一张空椅子，建立“这里曾有人一起工作”的感觉。小灯请玩家协助完成订单。
2. 包装车间：玩家恢复装配台，纽扣找出灯壳，提到“以前有个孩子总问最后谁关灯”。
3. 仓库：取得旧图框。玩家取出装配图，看到背面的留言，认出自己的笔迹：“给最后下班的人。回家的路也要亮。”揭示必须位于主线路径，不能藏在可错过的支线里。
4. 最终装配：玩家已经知道礼物属于谁，主动安排生产线制作南瓜灯。完成后亲手提起灯，交给小灯，而不是只观看过场。
5. 结尾：小灯说“那这次，我们一起下班。”三只幽灵带着灯走向门外的小镇游行。工厂挂上“今晚提前下班”，留下安全的暖色灯光。

故事语气：温暖、有少量工作日常笑话，避免长篇身世解释。对白可逐句快速推进；关键玩法目标独立显示，不因跳过对白而丢失。故事仅承诺建立情感体验，不将“学会感恩”写成已验证的学习成果。

## 4. 核心学习目标

主目标：玩家通过观察机器的依赖关系，在有限共享资源下安排操作顺序；当环境条件改变时重新规划。
次目标：玩家预测巡检行为，利用空间遮挡与可控的机器声音改变安全搬运时机。

| 能力 | 安全教学 | 新用途 | 验证证据 |
|---|---|---|---|
| 放置货箱 | 箱子压住板，门开启；移走则关闭 | 箱子挡住巡检视线；同一箱子在开门和掩护之间重新配置 | 无逐步提示下，玩家解释为何移动箱子并完成新布局 |
| 分配核心 | 插入供电，拔出停机；产物保留 | 一枚核心先加工灯壳，再转移给运输／装配设备 | 玩家能判断哪台机器可以先断电，避免仅随机试插 |
| 预测与改变巡检路线 | 透过安全窗观察巡逻、声音调查、视线中断 | 在最终场景用机器声音主动调动巡检，再运送核心 | 玩家说明声音会引发什么行为，并成功利用该行为 |

拟用于报告的英文概述：
The game asks players to plan an action sequence under shared-resource constraints. Players observe which machine states require continuous power, which completed outputs persist, and how moving a crate or power core changes the available route. Later challenges ask them to revise that plan while accounting for a predictable inspector whose attention can be redirected by machine sounds.

这是设计意图；完成试玩后根据实际行为修订，不能提前写成已经证实的学习成效。

## 5. 可推演的基本规则

- 玩家一次只能搬运一个货箱、能源核心或故事物件。搬运时可正常观察，速度暂不降低，避免靠慢行增加时长。
- 放置必须在可达、无重叠的有效表面。无效放置显示原因，物品保留在手上；关键物品不能丢入不可达区域。
- 压力板由货箱持续占用才开启对应门。玩家站上也可触发，但离开即失效，用教学演示为何需要箱子。
- 每个插座容纳一枚核心；核心不消耗、不复制。未供电机器不能启动。
- 机器运行需要持续供电；拔掉核心立刻停止。加工过程可继续，完成的产品与已完成任务永久保留。
- 可通行的门与运输设备必须明确区分“持续供电”及“完成后保持解锁”，使用图标和文本，不能只靠颜色。
- 调查声由机器从停机切换到运行的事件触发，不能仅让玩家无条件反复按一个无意义诱饵按钮。巡检调查后会返回巡逻；所有时长在原型中调试。
- 视线受墙和货箱遮挡。巡检只在指定车间执勤；进入安全区结束追赶。已完整发现后，单纯站在手持货箱后面不会立即清空警觉。
- 巡检接触玩家后，局部搬运阶段重置到其起点。保留已完成加工和剧情；恢复该阶段的箱子、核心、玩家及巡检位置，避免物品散落形成死局。
- 货箱与能源互相依赖的谜题要有可逆解法；不能把唯一核心永久锁在需要该核心才能打开的门后。
- 通关条件：完成灯具装配并交给小灯。无战斗、无生命值消耗、无全局倒计时。

## 6. 关卡结构

| 区域 | 具体挑战 | 故事和声音变化 | 目标时间（未测） |
|---|---|---|---|
| 门厅与教学间 | 用箱子持续开门；给试机台供电；安全窗观察并亲自触发一次巡检调查 | 小灯介绍工作，稀疏音乐盒旋律 | 1–1.5 分钟 |
| 包装车间 | 一枚核心先启动加工台，保留产物后拔出，再供电运输台；箱子保持旁门可通行 | 取出灯壳，纽扣提供童年伏笔；加入拨弦 | 1.5–2 分钟 |
| 仓库 | 调整箱子遮挡，在巡检转身或调查机器时运送图框；离开时重新配置开门箱子 | 发现订单背面；降低机器声，留出阅读空间 | 1.5–2 分钟 |
| 最终装配区 | 把已知规则组合：同一核心分阶段加工和运输，移箱子恢复路线，利用机器启动声创造搬运机会 | 主旋律逐渐完整，机器声音加入节奏 | 2–2.5 分钟 |
| 交付与下班 | 搬起成品，送给小灯，走到出口 | 工厂同事加入游行，完整主题变奏 | 0.5–1 分钟 |

以上合计约 7–9 分钟，仅为设计预算。对话和音乐不得强制延长到预算时长。最终谜题必须在纸面布局及原型中验证，保证存在清楚且可逆的解法。

## 7. Design Schemas

优先采用两个有明确课堂支持、能在玩法中验证的 schema：

### Games as Systems of Information（Rules of Play 86–95）
玩家始终可见当前目标、核心位置（在已探索区域）、插座状态、机器供电与加工状态、巡检警觉提示。未知的是未探索区域布局和新组合的解法。通过观察和尝试获得知识，不能通过隐藏必要操作说明制造难度。故事信息与规则信息分别记录：订单揭示是叙事信息，能源依赖和巡检反应是决策信息。

### Games as Systems of Uncertainty（68–84）
巡逻和机器按稳定规则运行。首次游玩时，玩家不确定自己的行动顺序和搬运时机能否成功；通过观察、尝试、反馈降低不确定性。无须随机抓人或随机改变谜题答案。知识与操作熟练可以改善表现。

### 条件采用：Games as Emergent Systems（46–67）
只有在实际规则组合允许不同有效策略时才加入。例如同一最终场景中，玩家可以用箱子铺设较安全的遮挡路线，也可以用机器声音制造短暂窗口。若最终实现只有预设按钮顺序，就不要声称具有丰富涌现性。需要试玩记录具体策略作为证据。

不为凑数量硬加 Cybernetic Systems。若以后确有监测、比较和调节组成的反馈机制，再准确描述；播放成功音效本身不足以证明一个平衡反馈回路。

## 8. 模式与 FSM

Gameplay modes：
1. 探索／解谜：第一人称可控镜头、移动、搬运、观察和互动。潜行是这一模式下的挑战，不因名字不同就强行作为独立小游戏。
2. 阅读／对话：局部聚焦信息和角色，可推进或关闭，移动禁用，世界暂停，避免读文字时被抓。只在安全互动点触发。
3. 交付尾声：玩家仍可携带成品和步行，交付触发有限的演出；演出期间哪些输入禁用要写清楚。
Shell screens：主菜单、暂停与音量设置、结束界面。具体采用哪些界面，以最终实现为准。

玩家 FSM 提案采用层级状态，避免把“行走”和“搬运”当成互斥状态：
- Active 内有 EmptyHands 与 Carrying 两种持物状态，两者均允许站立和行走。
- EmptyHands 在有效拾取时进入 Carrying；有效放置／插入／交付后返回 EmptyHands。
- Active 进入 Reading 时记录持物状态，关闭后恢复。仅安全阅读点允许进入。
- Active 被巡检接触进入 Resetting，恢复局部状态后进入 Active。
- 交付成品后进入 Ending；Ending 不响应一般谜题输入。
- Paused 为世界级暂停，冻结巡检与机器计时，恢复原状态；不丢弃手中物品。

巡检 FSM：
- Patrol：按路线巡逻。有效机器声进入 Investigate；看见玩家进入 Alert。
- Investigate：前往声源，观察后返回；看见玩家进入 Alert。
- Alert：显示清楚预警。持续可见超过阈值进入 Approach；视线中断则转 Search。
- Approach：接近玩家；接触触发局部重置，失去视线转 Search。
- Search：调查最后可见位置，限定时间后 Return；重新看见则 Alert。
- Return：回到巡逻路线，然后 Patrol。
优先级：已发现玩家时不被新机器声立即取消目标。预警、调查和搜索时长及视距均需原型调试，不能以模糊词留在最终规则里。

动画证据：玩家可见手部的拾取、携带、放置动作；幽灵的悬浮、发现、调查、庆祝表现。最终根据使用的角色资源确认动画覆盖，不以摄像机晃动充当全部角色动画。

## 9. 音乐与情绪

音乐目标是可记住、适合循环的温暖主题。先确定一段主旋律，再以不同配器表现工厂恢复，不能仅做互不相关的背景曲。
- 门厅：音乐盒或轻钢片琴，留空间听环境。
- 车间：加入轻拨弦和柔软低音。
- 巡检注意：短提示音和轻打击乐，避免尖锐突响；视觉也提供同样信息。
- 读到留言：降低配器密度，玩家自行控制阅读时间。
- 交付：完整旋律回归。关键感动来自玩家刚完成的行为。
音乐、环境和效果分别控制音量；授权和制作方式要如实记录。目前未制作或试听任何配乐，不能承诺现有音乐品质。

## 11. 试玩计划与后续工作

本轮只完成资料审阅和设计，不启动开发。
下一步按顺序进行：
1. 在本方案上确定故事、学习目标和规则；制作纸面关卡布局，推演至少两条有效行动顺序并排查死局。
2. 获准开始开发后，先做可玩的机制原型，尽早让陌生玩家尝试，再扩展成完整关卡。不要等待所有美术、故事和音乐定稿才首次试玩。
3. 试玩第一轮只看是否理解规则与是否存在无脑绕过。第二轮看新用途是否被理解、卡点与节奏。最后一轮从发布包完整游玩，验证完成时间和故事理解。
4. 覆盖不同熟练程度的人，包括首次接触者和较熟练者；不声称小样本能保证所有玩家都用时 5–10 分钟。
5. 每次记录：版本、玩家经验、是否外部提示、主线时长、阅读时间、重试、卡点、实际策略、原话反馈、修改和复测结果。
6. 将最终行为、实际参数及平台验证结果回填报告。High Concept、Game Script、对白附录、FSM、素材来源和迭代记录必须与同一最终版本对应。

关键测试提问：
- 为什么刚才把核心从这台机器拔走？
- 如果箱子换到这里，会改变哪些事情？
- 呼噜为什么走到那边？下一次你准备怎么过去？
- 最后一盏灯是给谁的？你在什么时候发现？
避免只问“你觉得学会了吗”或暗示正确答案。
